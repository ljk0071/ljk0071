모바일·데스크톱 레이아웃 가이드

Tailwind로 한 화면을 모바일과 데스크톱 양쪽에 맞출 때 쓰는 판단 기준을 모았어요. 작은 것에서 큰 것 순서로 읽어요. 한 줄 배치(1부), 섹션 구조(2부), 배치 말고 달라지는 것(3부) 순이에요.

데모 보는 법
  • 버튼으로 방식을 바꾸고 "부모 폭" 슬라이더로 화면이 좁아지는 상황을 만들어요.
  • 회색 점선은 부모 요소, 파란 점선은 묶음이에요.
  • 데모는 창 폭이 아니라 부모 폭이 넓어질 때(520px 이상) 데스크톱 배치로 바뀌어요. 코드에서 lg:가 붙은 클래스가 그때 적용되는 부분이에요.
  • "HTML 코드 보기"를 펼치면 그 모형의 코드가 나와요. 클래스를 누르면 그 클래스가 꺼지고 모형에 바로 반영돼요. 눌러도 모형이 그대로면 그 이유가 코드 아래에 나와요.
  • 모형은 코드에 적힌 태그와 클래스를 그대로 달고 있어요. 코드에 없는 건 색, 테두리, 글자 크기, 안쪽 여백 같은 꾸밈뿐이에요. 모형 안은 Tailwind의 기본 초기화(제목과 문단의 바깥 여백 0, 목록 점 없음)와 break-keep이 걸린 상태예요.
  • 폰에서는 화면이 좁아서 데모가 데스크톱 배치까지 넓어지지 못해요. 데스크톱 브라우저에서 보고, (호버와 터치)만 폰에서도 열어 보세요.

목차

1부한 줄 배치하기: flex와 grid

요소 몇 개를 한 줄에 놓을 때 flex와 grid 중 무엇을 쓸지 정해요.

flex와 grid의 차이: 누가 폭을 정하나

flex — 자식이 정해요각 요소가 자기 내용만큼 폭을 차지하고, 남는 공간을 나눠 가져요. 한 줄로 나열할 때 써요.
grid — 부모가 정해요부모가 열을 먼저 선언하고 요소는 그 칸에 들어가요. 같은 열의 칸은 폭이 같아요. 여러 행의 열을 맞출 때 써요.

어느 쪽이 더 좋은 게 아니에요. 아래 두 데모에서 한 번은 grid가, 한 번은 flex가 맞아요.

grid가 맞는 경우: 여러 행의 열을 맞출 때

랜딩 페이지의 반응 지수 막대와 같은 구조예요. 행마다 라벨 · 막대 · 숫자가 반복돼요.

해 보기버튼을 왼쪽부터 차례로 누르면서 막대의 시작점과 끝점을 보세요. 첫 라벨도 길게 바꿔 보세요.

grid-cols-[6rem_1fr_3rem] 읽는 법

  
대괄호 안의 _는 공백이에요. CSS로는 grid-template-columns: 6rem 1fr 3rem, 곧 열 세 개의 폭이에요.

  

  

    
값뜻정하는 법

    
6rem라벨 열. 고정 폭 (보통 96px)가장 긴 라벨이 들어가고 조금 남는 폭

    
1fr막대 열. 남는 폭 전부정하지 않아요. 부모 폭에서 나머지를 뺀 값이에요

    
3rem숫자 열. 고정 폭 (보통 48px)가장 긴 숫자 "100%"가 들어가는 폭

  

  

  
부모가 320px이고 간격이 12px이면 막대 열은 320 − 96 − 48 − 12 × 2 = 152px이에요. 위 데모에서 "grid (폭 고정)"을 고르고 부모 폭을 움직이면, 라벨과 숫자는 그대로고 막대 폭만 바뀌어요.

  

    
흔한 방식행마다 grid-cols-[6rem_1fr_3rem]를 반복해요. 폭을 직접 정해야 하고 더 긴 이름이 들어오면 다시 정해야 해요. 행이 서너 개고 데이터가 정해져 있으면 충분해요.

    
더 나은 방식부모에 grid-cols-[auto_1fr_auto]를 한 번 선언하고 각 행은 grid-cols-subgrid로 물려받아요. 가장 긴 라벨에 맞춰 열 폭이 스스로 정해져요. 데모의 네 번째 버튼이에요.

2부구조 잡기: 묶음

  
한 화면을 모바일과 데스크톱 양쪽에 맞추려면, 무엇을 무엇과 묶을지가 먼저 정해져야 해요.


  
묶음이 왜 필요한가

  
묶음은 요소 몇 개를 감싸는 부모 요소예요. 래퍼(wrapper)라고도 불러요. div일 때가 많고, 의미가 있으면 section, ul, figure를 써요.

  
묶음이 필요한 이유는 grid와 flex가 바로 아래 자식만 배치하기 때문이에요. "제목·설명·버튼은 왼쪽, 카드는 오른쪽"을 시키려면 제목·설명·버튼이 먼저 한 덩어리로 묶여 있어야 해요.

  
배치가 바뀔 때 같이 움직이는 것끼리 한 부모에 넣어요.모바일에서 세로로 쌓이다가 데스크톱에서 좌우로 갈라진다면, 갈라지는 두 덩어리가 각각 묶음이에요. 그 둘의 공통 부모가 lg:grid-cols-2를 받는 자리예요.

묶음을 찾는 질문

  
묶음은 감각으로 정하는 게 아니에요. 대부분 시안에서 확인할 수 있는 질문 세 개로 정해져요. 감각처럼 보이는 건 이 질문에 여러 번 답해 본 사람이 빨리 답하는 거예요.


  
질문 1. 간격이 어디서 넓어지나

  
가장 기계적인 방법이에요. 요소 사이 간격을 재서 주변보다 눈에 띄게 넓은 곳이 묶음의 경계예요. 디자이너가 간격으로 이미 묶음을 표시해 둔 거예요.

  
해 보기숫자를 눌러 간격을 바꿔 보세요. 전부 같게도 만들어 보세요.

  

    

      

      
    
    
    
    
    
  
    

  
    질문 2. 두 요소가 같이 다니나
    
  
    요소 두 개를 골라 모바일 시안과 데스크톱 시안에서 비교해요.
    
  
    
  
    
    
    두 요소가…그러면
    
    
    모바일에서는 위아래로, 데스크톱에서는 좌우로 놓인다 (또는 그 반대)방향을 바꾸는 부모 아래에 둘을 둬요. 예: grid lg:grid-cols-2
    
    
    붙은 채로 함께 움직여서 다른 덩어리의 옆으로 간다둘을 감싸는 묶음을 만들어요. 그 묶음이 통째로 움직여요.
    
    
    배경, 테두리, 최대 폭을 같이 쓴다그 배경이나 테두리를 가진 상자로 감싸요.
    
    
    합쳐서 한 단어로 부를 수 있다 (카드, 내비게이션, 목록)의미가 있는 요소로 감싸요. 예: figure, nav, ul
    
    
    어느 것도 아니다묶지 않아요. 형제로 둬요.
    
  
    
  
    

  
    질문 3. 이 div를 지우면 뭐가 깨지나
    
  
    반대 방향의 확인이에요. 이미 있는 div가 정말 필요한지 의심될 때 써요. 지워도 깨지는 게 없으면 묶음이 아니니 지워요.
    
  
    해 보기경우마다 "div 지우기"를 눌러 보세요.

    질문으로 안 정해질 때
    
  
    
  
    
    
    상황정하는 방법
    
    
    같은 결과를 내는 구조가 여러 개HTML이 덜 깊은 쪽을 골라요.
    
    
    간격이 비슷하거나 데스크톱 시안이 없음의미로 묶어요. "제목 + 설명 + 버튼", "사진 + 설명글", "라벨 + 입력칸"처럼 한 가지를 설명하는 요소들은 데스크톱에서도 거의 항상 같이 움직여요.
    
    
    나중에 요소가 늘어날 것 같음기획을 아는 만큼만 맞힐 수 있어요. 모르면 지금 시안대로 해요.
    
  
    
  
    
  
    여기서 틀려도 비용은 작아요. 간격을 부모가 갖게 해 두면() 묶음을 바꾸는 건 div 하나를 넣고 빼는 일이에요.
    

  
    작업 순서: 구조는 먼저, 스타일은 모바일부터
    
  
    모바일 화면을 다 만든 뒤 데스크톱에서 묶으려 하면 어려워요. 이미 맞춰 놓은 모바일 간격을 다시 손봐야 하기 때문이에요.
    
  
    "모바일 우선"은 CSS를 쓰는 순서에 대한 규칙이에요. HTML 구조는 두 시안을 모두 보고 먼저 정해요.

    묶음을 코드로 쓸 때 지킬 세 가지
    

  
    ① 묶음 사이 간격은 부모가 갖기
    
  
    묶음과 묶음 사이 간격을 자식의 margin으로 주면, 배치가 바뀔 때 그 여백이 엉뚱한 곳에 남아요. 부모의 gap으로 주면 세로로 쌓일 때는 위아래 간격이, 가로로 놓일 때는 좌우 간격이 돼요.
    
  
    해 보기두 방식을 바꿔 가며 부모 폭을 줄였다 넓혀 보세요. 넓을 때 파란 점선 상자의 아래쪽을 보세요.
    
  
    
    
    
      
    
        
        
      
    
      
    
    
    
    
    
    
    
    HTML 코드 보기
    클래스를 누르면 꺼지고, 다시 누르면 켜져요. 눌러도 모형이 그대로면 그 이유가 코드 아래에 나와요.
    
  
    
  
    묶음 안에서 요소마다 간격이 달라 gap 하나로 안 될 때는 뒤따르는 요소에 mt-*를 줘요. 방향은 위쪽 하나로만 쓰고 묶음의 마지막 요소 아래에는 여백을 두지 않아요. 지금 dashboard.tsx가 이 방식이에요. 글 묶음과 카드 사이는 gap-8 lg:gap-20, 글 묶음 안은 mt-5와 mt-1이에요.
    

  
    ② 배경은 바깥 요소에, 폭 제한과 배치는 안쪽 요소에
    
  
    배경은 화면 끝까지 가야 하고 내용은 최대 폭 안에 있어야 해요. 한 요소가 둘을 다 할 수 없으니 나눠요.
    
  
    <section class="bg-paper">                  ← 배경: 화면 끝까지
  <div class="container-page                ← 폭 제한: 최대 폭과 좌우 여백
              grid gap-8
              lg:grid-cols-2 lg:gap-20">    ← 배치가 바뀌는 지점
    <div>...</div>                          ← 묶음 1: 제목 · 설명 · 버튼
    <figure>...</figure>                    ← 묶음 2: 카드
  </div>
</section>
    
  
    dashboard.tsx 맨 위 주석 "섹션은 전체 폭, 내용만 container-page"가 이 규칙이에요.
    

  
    ③ HTML 순서는 모바일에서 읽는 순서로
    
  
    스크린리더와 탭 키는 화면에 보이는 위치가 아니라 HTML 순서를 따라요. 데스크톱은 CSS로 배치만 바꾸고 순서는 건드리지 않아요.
    

  
    상자가 두 시안에서 안 맞을 때
    
  
    모바일과 데스크톱의 모양이 가로·세로 전환보다 더 많이 다를 때예요. 방법이 세 가지 있어요. 위에서부터 시도해서 되는 첫 번째에서 멈춰요. 아래로 갈수록 관리할 것이 늘어나기 때문이에요.
    
  
    
  
    
    
    방법맞는 경우주의할 점
    
    
    1. CSS로 자리만 옮기기요소는 같고 위치만 달라요.화면에 보이는 순서와 HTML 순서가 달라져요. 읽는 순서가 뒤바뀔 정도면 쓰지 않아요.
    
    
    2. 둘 다 두고 하나만 보이기작은 조각의 모양이 달라요. 예: 햄버거 버튼 ↔ 가로 메뉴큰 덩어리에 쓰면 같은 내용을 두 번 관리해요.
    
    
    3. JS로 하나만 그리기모양보다 동작이 달라요. 예: 카드 목록 ↔ 표, 하단 시트 ↔ 팝오버서버에서 화면을 미리 그리는 구조면 처음에 다른 쪽이 잠깐 보일 수 있어요.

    Pinterest핀에 올리면 저장 버튼 표시길게 누르면 메뉴가 펼쳐짐
    
    
    Airbnb카드에 올리면 사진 넘김 화살표 표시사진을 좌우로 밀어서 넘김
    
  
    
  
    
  
    공통점은 같은 목적을 장치에 맞는 동작으로 바꿨다는 거예요. YouTube는 양쪽 다 "누르기 전에 미리 보기"가 목적이에요. 서비스 화면은 수시로 바뀌니 지금은 다를 수 있어요.
    

  
    CSS만으로 되는 좌우 넘김
    
  
    
    
    
    
    손가락으로 밀거나 트랙패드로 넘기면 카드 단위로 멈춰요. 부모의 flex overflow-x-auto snap-x snap-mandatory와 자식의 snap-start면 돼요. 하단 시트나 밀어서 삭제처럼 손가락을 따라가는 동작은 보통 라이브러리를 써요.
    
    
    HTML 코드 보기
    클래스를 누르면 꺼지고, 다시 누르면 켜져요. 눌러도 모형이 그대로면 그 이유가 코드 아래에 나와요.
    
  
    

  
    
    
    흔한 방식lg:를 기준으로 데스크톱에만 호버 효과를 넣고 모바일은 비워 둬요. 모바일이 밋밋해지고 아이패드에서 어긋나요.
    
    
    더 나은 방식입력 장치 조건으로 나누고 호버 효과마다 터치에서의 짝을 같이 정해요.
    
  
    
  
    지켜야 할 한 가지호버로만 볼 수 있는 정보나 기능은 만들지 않아요. 호버는 더 즐겁게 하는 층이고 없어도 쓸 수 있어야 해요. 키보드 사용자도 호버를 못 하니 focus-visible:을 같이 붙여요.
    

  
    우선순위와 이동: 일하는 화면
    
  
    폰은 한 손으로 잠깐씩 쓰고 데스크톱은 책상에서 두 손으로 오래 써요. 그래서 조작을 반복하는 화면은 배치 말고도 아래가 달라져요.
    
  
    
  
    
    
    달라지는 것모바일데스크톱
    
    
    우선순위한 화면에 한 가지 일. 나머지는 접어요.목록과 상세를 나란히 펼쳐요.
    
    
    이동 방식엄지가 닿는 아래쪽 탭위쪽이나 옆쪽 메뉴
    
    
    입력입력 칸을 줄이고 선택지나 자동 완성으로타이핑, 단축키
    
    
    장치 기능카메라, 공유, 위치끌어다 놓기, 여러 개 한꺼번에 처리
    
  
    
  
    
  
    가장 흔한 예가 목록과 상세예요. 넓으면 둘을 나란히 보여 주고 좁으면 한 번에 하나만 보여 줘요.
    
  
    해 보기넓은 상태에서 항목을 눌러 보고 부모 폭을 줄인 뒤 다시 눌러 보세요.
    
  
    
    
    
      
    
    
    
    
      
    
        
      
        
      
          
          
      왼쪽에서 하나를 고르세요.
      
        
      
      
      
    
      
    
      내용과 기능은 양쪽이 같아요. 달라진 건 "한 번에 무엇을 보여 주나"와 "어떻게 이동하나"예요. 좁을 때만 뒤로 가기 버튼이 생겨요.
      
  
      
  
      이런 차이는 의 방법 2나 3으로 만들어요. 위 데모는 방법 2예요.
      
  
      모바일을 먼저 설계하라는 조언(Luke Wroblewski, 『Mobile First』)도 같은 맥락이에요. 좁은 화면에서 먼저 정하면 무엇이 중요한지 골라야 하고 데스크톱은 거기에 여유를 더하는 작업이 돼요. 반대로 하면 데스크톱 화면을 좁은 화면에 구겨 넣게 돼요.
      

  
  
      마무리정리
      
  
      읽은 순서와 실제로 작업하는 순서는 달라요. 화면 하나를 만들 때는 아래 순서로 해요.
      

  
      한 화면을 만드는 순서
      
  
        
    
      1. 두 시안을 나란히 놓고 상자를 그려요.간격이 넓어지는 곳과 좌우로 갈라지는 곳이 경계예요. → , 
        2. 
    
      2. 상자대로 HTML 구조를 써요.순서는 모바일에서 읽는 순서로 쓰고 배경과 폭 제한은 다른 요소에 둬요. → 
        3. 
    
      3. 묶음마다 flex인지 grid인지 골라요.폭을 서로 맞춰야 하면 grid, 내용 길이에 맡기면 flex예요. → 
        4. 
    
      4. 모바일 스타일을 쓰고, 달라지는 것만 lg:로 더해요.묶음 사이 간격은 부모의 gap으로 줘요. → , 
        5. 
    
      5. 상자가 안 맞는 조각만 따로 처리해요.CSS로 자리 옮기기, 숨기기, JS 순서로 시도해요. → 
        6. 
    
      6. 호버 효과를 넣을 때마다 터치에서의 짝을 정해요.호버로만 쓸 수 있는 기능은 만들지 않아요. → 
        7. 
    
      7. 일하는 화면이면 우선순위와 이동 방식을 따로 정해요.내용과 기능은 줄이지 않아요. → ,
